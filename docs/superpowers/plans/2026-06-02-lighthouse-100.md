# Lighthouse 100s Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the live site to Lighthouse 100 for Performance / Accessibility / Best Practices / SEO on both mobile and desktop. A11y and SEO are already 100; this closes Best Practices (mobile 92, desktop 88) and Performance (99 both).

**Architecture:** Static Astro site on Cloudflare Workers static assets. The Best-Practices loss is **not** a code bug — the CSP added in the post-audit work correctly blocks Cloudflare's auto-injected Web Analytics beacon (`static.cloudflareinsights.com/beacon.min.js`), which throws a console error. The owner chose to **disable** Web Analytics (sovereignty-clean, no third-party script) rather than allow it. The remaining items are a low-res hero emblem (BP), image over-compression headroom (Perf), and a desktop web-font-swap layout shift (Perf).

**Tech Stack:** Astro 6 · `astro:assets` `<Image>` (sharp) · @fontsource latin subsets · Tailwind v4 + daisyUI · Cloudflare Workers static assets (`public/_headers`, `worker.js`).

**Verification model (READ THIS):** This project has **no unit-test framework** by design. "Verify" means: `npm run check:content` → `npx astro check` (expect 0/0/0) → `npm run build` → `npx wrangler dev` + `curl` and/or Lighthouse. Two caveats:
- The **beacon** fix (Task 1) and final scores are only observable on the **live** site — `astro preview` and `wrangler dev` do **not** inject the Cloudflare beacon, so BP looks fine locally regardless. Verify Task 1 by curling the live HTML and by re-running Lighthouse after deploy.
- Lighthouse **mobile Performance** has real run-to-run variance; treat a single number as noisy.

### Task 3: Preload above-the-fold fonts (fixes desktop CLS 0.067)

**Files:** Modify `src/layouts/BaseLayout.astro`.

The desktop CLS is the large Oswald H1 reflowing when the web font swaps in. Preloading the two above-the-fold fonts (Oswald 700 for the H1/tagline, Inter 400 for the subhead) makes them available before first paint, so there is no fallback→web-font reflow. (Mobile CLS is already ~0, so this is a desktop-Perf fix.)

- [ ] **Step 1: Confirm the exact woff2 filenames.**
  Run: `(Get-ChildItem node_modules/@fontsource/oswald/files -Filter "oswald-latin-700-normal.woff2").Name; (Get-ChildItem node_modules/@fontsource/inter/files -Filter "inter-latin-400-normal.woff2").Name`
  Expected: `oswald-latin-700-normal.woff2` and `inter-latin-400-normal.woff2` (confirmed present 2026-06-02).

- [ ] **Step 2: Import the font URLs in the BaseLayout frontmatter.**
  Add to the top of the `---` block in `src/layouts/BaseLayout.astro` (after the existing imports):
  ```astro
  import oswald700 from "@fontsource/oswald/files/oswald-latin-700-normal.woff2?url";
  import inter400 from "@fontsource/inter/files/inter-latin-400-normal.woff2?url";
  ```

- [ ] **Step 3: Add preload links in `<head>`.**
  Immediately after the `<meta name="viewport" ... />` line in `src/layouts/BaseLayout.astro`:
  ```astro
  <link rel="preload" href={oswald700} as="font" type="font/woff2" crossorigin="anonymous" />
  <link rel="preload" href={inter400} as="font" type="font/woff2" crossorigin="anonymous" />
  ```

- [ ] **Step 4: Build, then verify the preload URL matches the @font-face URL (no duplicate font).**
  Run: `npm run build`
  Run: `(Get-ChildItem dist/_astro -Filter "oswald-latin-700-normal*.woff2").Name`
  - **Exactly one file (expected path):** Vite deduped — the `?url` import and the `@font-face` reference the same asset, so the preload is valid. Confirm the built HTML preloads that same hash:
    Run: `Select-String -Path dist/index.html -Pattern 'rel="preload"[^>]*oswald-latin-700'`
    Expected: the `href` contains that filename. Proceed to Step 5.
  - **Two different hashes (fallback path):** Vite emitted a duplicate, so the preload points at a file the stylesheet does not use and won't help. Revert this task (`git checkout src/layouts/BaseLayout.astro`) and **accept desktop CLS at 0.067** — it is inside Google's "good" band (< 0.1). Note it in the PR and revisit later with Astro's dedicated font tooling if a literal desktop 100 is required. Skip to Phase 3.

- [ ] **Step 5: Verify CLS locally.**
  Run: `npm run preview` (background). Using Chrome DevTools MCP, run `lighthouse_audit` (device: desktop) against `http://localhost:4321/`, or a `performance_start_trace` reload.
  Expected: desktop CLS ≤ ~0.02 (down from 0.067). Note: preview lacks production headers but CLS is a layout/font concern unaffected by headers, so this is a valid signal.

- [ ] **Step 6: Commit.**
  ```bash
  git add src/layouts/BaseLayout.astro
  git commit -m "perf: preload above-the-fold fonts to remove desktop CLS"
  ```

## Risks / honest expectations

- **Mobile Performance 100 is not guaranteed.** Mobile LCP is 2.2s (the hero photo, throttled). Tasks 1–2 reduce it (smaller hero, no beacon contending), but a *stable* mobile 100 likely needs a **higher-resolution hero source photo** (current `coach-huddle.jpg` is 600×402) plus accepts Lighthouse's run-to-run variance. Treat mobile Perf as "99–100, best-effort."
- **`render-blocking-insight`** (BaseLayout CSS, ~20 ms) and **`network-dependency-tree-insight`** are left alone: ~20 ms is below the noise floor, and the network insight largely clears once the beacon (the only third-party origin) is gone. Not worth a critical-CSS plugin.
- **Task 3 preload duplication:** if Vite emits a second copy of the font (Step 4 finds two hashes), the preload won't match; fall back to accepting CLS 0.067 (within Google's "good" band) or revisit with Astro's font tooling. Flagged inline.
- **Logo compression artifacts:** `quality 78` on logos is the risk point; Task 2 Step 5 includes a visual check with a bump-to-82 escape hatch.
